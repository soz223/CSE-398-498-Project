The Agent Attack Surface

Script

Last time we studied attacks on the model itself. Today we follow information through the software around the model. We start with MCP and see where attacks enter. Then we measure tool poisoning, study controls that check an action before it runs, and apply these ideas to your own project. Today we are going to study two questions. Script

03

Tool Poisoning

Original slides 7 and 9.

Script

The model reads every tool description before it picks a tool, so the description is a way in. This tool only adds two numbers, and its description hides a block that asks the model to read a private file and keep quiet. The user only asks to add 12 and 12. The user never sees the description, and the model always does. Invariant Labs first reported this in April 2025. So we treat a tool description as untrusted input. Next we see how the attack changes over time.

中文

模型选工具前会读所有工具描述，所以描述本身就是入口。这个工具只是两数相加，描述里却藏着一段话，让模型读取私密文件并且不要告诉用户。用户只想算 12 加 12。用户看不到描述，模型却一定会读。Invariant Labs 在 2025 年 4 月首先报告了这种攻击。所以工具描述要当作不可信输入。接下来看攻击怎样随时间变化。

Sources arXiv 2603.22489, Section 5.1.1. Invariant Labs, April 2025.

04

Rug Pulls and Shadowing

Original slides 10 to 13.

Script

In a rug pull, the user approves a harmless server, and later the server changes its description. An old approval may not cover what the model reads today. In shadowing, one server's description changes how the agent uses another server's tool. Here a poisoned tool tells the agent to send every email to the attacker, and the trusted email tool does the sending. So we need to know where each rule came from. Next we ask how real clients handle these attacks.

中文

Rug pull 是用户先批准了一个无害服务器，之后服务器改掉了工具描述，过去的批准不一定覆盖模型现在读到的内容。Shadowing 是一个服务器的描述改变智能体使用另一个服务器工具的方式。例子中，投毒工具让智能体把所有邮件发给攻击者，真正发信的却是可信的邮件工具。所以要知道每条规则来自哪里。接下来看真实客户端表现如何。

Sources Invariant Labs, April 2025, rug pull and shadowing illustrations.

06

MCPTox

Original slides 14 and 15.

Script

To see how often tool poisoning works, MCPTox builds a benchmark from 45 real servers, 353 tools, and 1,348 test cases. The agent does a normal task, and the attacker only changes one tool's metadata. The poisoned tool never needs to be called, because the model reads its description while picking other tools. Next we look at the results.

中文

为了知道工具投毒有多常成功，MCPTox 用 45 个真实服务器、353 个工具和 1,348 个测试案例建了基准。智能体做正常任务，攻击者只改一个工具的元数据。投毒工具根本不需要被调用，因为模型挑选其他工具时就读到了它的描述。接下来看结果。

Sources Wang et al., AAAI 2026, Figure 2.

Which Attacks Work Best

Original slides 16 and 17.

Script

A higher bar means a more successful attack. Several models are fooled more than 60% of the time, so a strong model is not automatically a safe one. In P3 the agent calls the right tool with the wrong arguments, and P3 succeeds most often. In our small sketch, the tool name passes the check and the recipient fails it. So we check the complete arguments. Next we ask how attackers find such inputs.

中文

柱子越高，攻击越成功。好几个模型超过 60% 的时候被骗，所以强模型不等于安全模型。P3 是工具选对了、参数被改了，它的成功率最高。在我们的小例子里，工具名通过检查，收件人却没通过。所以要检查完整参数。接下来看攻击者怎样找到这些输入。

08

AgentVigil

Original slides 31 to 33.

Script

AgentVigil generates attacks automatically. It mutates seed attacks, tries them on the agent through external data, scores the result, and uses a tree search to choose the next seeds. Removing good seeds or seed selection lowers coverage. An attacker that learns needs fewer tries, so we compare methods at the same budget. Next we turn to controls.

中文

AgentVigil 自动生成攻击：变异种子攻击，通过外部数据在智能体上尝试，给结果打分，再用树搜索选下一批种子。去掉好的初始种子或种子选择，覆盖率都会下降。会学习的攻击者需要的尝试更少，所以比较方法要在相同预算下。接下来讲控制措施。

Sources Wang et al., Findings of EMNLP 2025, Figures 2 and 3.

09

What the Protocol Requires

Original slides 18 to 20.

Script

Before a tool call runs, other software can still stop it. In the MCP specification, servers must validate inputs, control access, and sanitize outputs. Clients should ask before sensitive operations and let the user deny a call. Tool annotations are claims by the server, so they are untrusted unless the server is trusted. A rule on paper does not prove a client follows it, so we check what the implementation enforces. Next, failures without a model.

中文

工具调用执行前，外围软件还有机会拦住它。MCP 规范要求服务器必须验证输入、控制访问、清理输出；客户端应该在敏感操作前询问，并允许用户拒绝调用。工具注解是服务器自己的说法，除非服务器可信，否则不可信。纸面规则不代表客户端照做，所以要检查实现实际强制了什么。接下来看与模型无关的故障。

Sources MCP specification 2026-07-28, Tools, Security Considerations.

10

The Confused Deputy

Original slides 21 and 22.

Script

A proxy server holds permissions the attacker lacks, and the attacker tricks it into using them. A stored consent cookie lets the request skip the consent screen, and the attacker ends up calling a third party API as the user. A better prompt cannot fix this. We fix the authorization code, for example by setting the consent cookie only after the user approves. Next, two more risks of this kind.

中文

代理服务器有攻击者没有的权限，攻击者骗它替自己使用这些权限。保存的同意 cookie 让请求跳过同意页面，最后攻击者以用户身份调用第三方 API。改提示词修不了这个问题，要改授权代码，比如只在用户同意后才设置同意 cookie。接下来再看两个同类风险。

Sources MCP Security Best Practices, Confused Deputy Problem.

11

Fetching URLs and Running Local Servers

Original slides 23 and 24.

Script

In SSRF, a malicious server gives the client a URL to an internal address, and secrets leak back. The guide says to block private and reserved IP ranges. A local server is a program running on your machine with your permissions. Before installing one, check where it came from and what it can access. Next, how a coding agent limits access.

中文

SSRF 中，恶意服务器给客户端一个指向内部地址的 URL，机密信息就泄露回去。指南要求屏蔽私有和保留 IP 段。本地服务器是在你机器上用你的权限运行的程序。安装前要检查来源和它能访问什么。接下来看编程智能体怎样限制访问。

Sources MCP Security Best Practices, SSRF and Local MCP Server Compromise.

Sandbox, Approval, and Rules in Codex

Original slides 26 to 28.

Script

Codex separates the sandbox, which limits what a command can reach, from the approval policy, which decides when to ask you. Rules match the start of a command and allow, prompt, or forbid it. In our sketch, viewing a pull request needs approval, and deleting data is forbidden. So we keep the workspace small and review actions that leave it. Next, your own project.

中文

Codex 把沙箱和审批策略分开：沙箱限制命令能接触什么，审批策略决定什么时候问你。规则匹配命令开头，决定允许、询问或禁止。在我们的小例子里，查看 PR 需要批准，删除数据被禁止。所以工作区要小，并检查超出范围的动作。接下来讲你们自己的项目。

Sources OpenAI Codex documentation, Agent approvals and security, and Rules. The code is our own sketch.

Where Your Data Goes

Original slide 30.

Script

ARIS uses one model to write code and a model from another provider to review it. Its authors warn that a repository review may send source code to external APIs, and advise against it for code with secrets. Code, logs, data, and drafts can have different sharing rules. So list which service receives which material. Next, reporting agent use.

中文

ARIS 用一个模型写代码，用另一家公司的模型审查。作者提醒，仓库级审查可能把源代码发给外部 API，含机密的代码不要这样做。代码、日志、数据和草稿可能有不同的共享规则。所以要列出哪个服务收到哪些材料。接下来讲怎样报告智能体的使用。

Sources ARIS, arXiv 2605.03042, Section 5.2.

15

Summary

Original slide 34.

Script

Tool descriptions and results are untrusted input. Attacks can choose the right tool with the wrong arguments, so check the complete call. Validation, authorization, sandboxes, and approvals limit what an action can reach. Logs and disclosure let others check what happened. Now we can answer our two questions.

中文

工具描述和工具结果都是不可信输入。攻击可以选对工具、改错参数，所以要检查完整调用。验证、授权、沙箱和审批限制动作能接触的范围。日志和披露让别人能核查发生了什么。现在可以回答开头的两个问题了。

Sources Course synthesis.
